# WILDLIFE ARENA

2–4 ฝูงสัตว์ บนสนามป่าเดียวกัน · ทุกคนวางแผนพร้อมกัน แล้วเฉลยผลพร้อมกัน · เกมละ 3–5 นาที

## Files
- `index.html` — ตัวเกมทั้งหมด (เมนู, สอนเล่น, จัดฝูง, rig/animation, บอท, netcode ฝั่ง client). เปิดไฟล์ตรงๆ = เล่นกับบอทออฟไลน์ได้
- `server.js` — server ตัวเล็ก (bundle แล้ว ไม่ต้อง `npm install`): เสิร์ฟ `index.html` + ห้อง WebSocket. ไม่มี database — ห้องอยู่ใน memory
- `server.source.js` — source ของ server (แก้ที่นี่ แล้ว `npm run build`)
- `design/`, `prototype/` — ไฟล์ concept เดิม

## ตั้งค่าเกม (โฮสต์ตั้งในห้อง / หรือตั้งตอนเล่นกับบอท)
| ตั้งค่า | ตัวเลือก |
|---|---|
| จำนวนฝูง | 2 / 3 / 4 |
| โหมด | ตัวใครตัวมัน (FFA) · ทีม 2v2 (แดง+ฟ้า vs เขียว+เหลือง, มองเห็นร่วมกัน, ยิงเพื่อนไม่โดน) |
| สัตว์ต่อฝูง | 3–6 (รวมสิงโต) |
| ซ้ำได้สูงสุด | 1 / 2 / 3 / ไม่จำกัด |
| สั่งได้ต่อรอบ | 1 / 2 / 3 / ทุกตัว |
| จำนวนรอบ | 5 / 8 / 12 / 20 / ∞ (เล่นจนเหลือฝูงหรือทีมเดียว) |
| ห้อง | สาธารณะ (โชว์ในล็อบบี้) / ส่วนตัว (เข้าด้วยรหัสเท่านั้น) |

## ล็อบบี้ออนไลน์
- **โปรไฟล์**: ตั้งชื่อ + เลือกรูปสัตว์ครั้งแรกที่เข้าเล่นออนไลน์ (สุ่มชื่อให้ได้ 🎲) · เก็บในเครื่อง แก้ได้จากปุ่มชื่อมุมขวาบน
- **แท็บออนไลน์**: จำนวนคนออนไลน์/ห้อง · ⚡ เข้าเล่นด่วน (หาห้องว่างให้ ถ้าไม่มีสร้างใหม่) · สร้างห้อง · ใส่รหัส · รายการห้องรอผู้เล่น (ชื่อห้อง, รูปผู้เล่น, ตั้งค่า) + ห้องที่กำลังเล่น
- **ในห้อง**: ทุกคนกด ✋ พร้อม → พาทุกคนไปจัดฝูงพร้อมกัน (30 วิ, ใครไม่ยืนยันจะสุ่มให้) · โฮสต์กด *เริ่มเลยไม่ต้องรอ* ได้ · คลิกที่นั่งว่างเพื่อย้ายที่/ย้ายทีม (โหมดทีม: ที่ 1+2 vs 3+4)
- โฮสต์ตั้งชื่อห้อง / ตั้งค่าเกม / เชิญคนออก (✕) · แชทในห้อง
- **แท็บเล่นกับบอท**: ตั้งค่าเกมแล้วเล่นออฟไลน์

## มือถือ
แตะเลือกตัว · ลากตัวเพื่อเดิน · เล็ง = แตะทิศ แล้วแตะซ้ำเพื่อยืนยัน · ลากพื้นเพื่อเลื่อน · สองนิ้วเพื่อซูม · แตะศัตรูดูข้อมูล · เล่นได้ทั้งแนวตั้งและแนวนอน

## Run (LAN)

```bash
npm start          # หรือ node server.js
```

```
Wildlife Arena
  Local:    http://localhost:3000
  Network:  http://192.168.x.x:3000   <- ส่งลิงก์นี้ให้เพื่อนใน Wi-Fi เดียวกัน
```

เข้าเกม → **เล่น** → ใส่ชื่อ → **สร้างห้อง** → กด *คัดลอกลิงก์ชวนเพื่อน* (ถ้าเปิดจาก localhost ลิงก์จะใช้ IP วง LAN ให้อัตโนมัติ).
เพื่อนเปิดลิงก์แล้วกด *เข้าห้อง* · ทุกคนกด *จัดฝูงของฉัน* · โฮสต์เลือกจำนวนฝูง (2 / 3 / 4) แล้วกด *เริ่มเกม*. ที่นั่งว่างเป็นบอท · 2 ฝูงจะเกิดคนละมุมตรงข้ามกัน
เล่นคนเดียวกับบอทก็เลือกได้ว่าจะเล่นกี่ฝูง

แก้ server แล้ว build ใหม่: `npm install && npm run build`

## ตั้งค่าด้วย .env
`npm start` อ่าน `.env` ข้างๆ `server.js` ให้อัตโนมัติ (ค่าจาก environment จริงจะชนะ `.env`) · ดูตัวอย่างใน `.env.example`

| env | ใช้ทำอะไร |
|---|---|
| `PORT` | พอร์ต (ค่าเริ่มต้น 3000) |
| `ANALYTICS_URL` + `ANALYTICS_WEBSITE_ID` | ใส่ครบทั้งคู่ = แทรก `<script src="{URL}/script.js" data-website-id=…>` ลงหน้าเกม · เว้นว่าง = ปิด |
| `ANALYTICS_RECORDER` | `true` = แทรก `recorder.js` เพิ่ม |
| `ANALYTICS_SCRIPT`, `ANALYTICS_RECORDER_SCRIPT` | เปลี่ยนชื่อไฟล์สคริปต์ (ค่าเริ่มต้น `script.js`, `recorder.js`) |

`.env` ไม่ถูก commit (อยู่ใน `.gitignore`) และไม่ถูกก๊อปเข้า Docker image — ตอน deploy ให้ตั้ง env ใน Dokploy/แพลตฟอร์มแทน

## Limits (env)
| env | default | |
|---|---|---|
| `MAX_ROOMS` | 200 | ห้องพร้อมกันสูงสุด |
| `MAX_CONN_PER_IP` | 12 | การเชื่อมต่อต่อ IP |
| `ROOMS_PER_IP_PER_MIN` | 6 | สร้างห้องต่อ IP ต่อนาที |
| ข้อความ | 20/วิ (burst 40) ต่อ socket · ข้อความละไม่เกิน 16 KB | |

หลัง reverse proxy server อ่าน IP จาก `X-Forwarded-For` · ใช้ instance เดียว (ห้องอยู่ใน memory)

## Deploy
Node host ไหนก็ได้ (Render, Railway, Fly.io, VPS/Dokploy) หรือ Docker: `docker build -t zoo-arena . && docker run -p 3000:3000 zoo-arena`.
WebSocket ใช้พอร์ตเดียวกับ HTTP · ถ้าเป็น HTTPS จะใช้ `wss://` เอง

## สอนเล่น
หน้าแรก → *เรื่องราว + สอนเล่น*: เริ่มด้วยฉากเล่าเรื่องในป่า ~25 วิ (ข้ามได้) แล้วต่อด้วยสอนเล่น 11 ขั้น: เป้าหมายของเกม → เดิน → ซ่อนในพุ่มหญ้า → ลองสกิลของทุกตัว → หลบให้สิงโตรอด → ล้มสิงโตศัตรู (นกฮูก แรด คาเมเลียน เต่า สิงโต หนู) · มีนิ้วชี้บอกว่าต้องกดตรงไหน ทำสำเร็จแล้วไปขั้นถัดไปเอง

## กติกา
- **เป้าหมาย: ปกป้องสิงโตของตัวเอง** — สิงโตล้ม = ทั้งฝูงตกรอบ · ล้มสิงโตฝูงอื่นให้หมด = ชนะ
- แต่ละฝูง: สิงโต (หัวหน้า) + เลือกอีก 3 จาก แรด / นกฮูก / คาเมเลียน / เต่า / หนู (ซ้ำได้ไม่เกิน 2)
- แต่ละรอบสั่งได้ **1 / 2 / 3 ตัว หรือทุกตัว** (โฮสต์ตั้งในห้องก่อนเริ่ม · ค่าเริ่มต้น 2) · เวลา 40 วิ หรือจนทุกคนกด *พร้อมแล้ว*
- เฉลยผล: ① ทุกตัวเดินพร้อมกัน (เดินชนกันเด้งกลับ) ② ลงมือ (โล่/คำราม → พุ่งชน → เฝ้ายิง → ซุ่มโจมตี → สแกน)
- **ชนกัน**: เดินเข้าช่องเดียวกัน / สลับที่กัน / เข้าช่องที่ตัวอื่นไม่ขยับ → เด้งกลับที่เดิมทั้งคู่
- **ยิงใส่กัน**: ทุกจังหวะในเฟสเดียวกันเกิดพร้อมกัน (นกฮูกยิงกัน = โดนทั้งคู่, ซุ่มโจมตีพร้อมกัน) · แรดพุ่ง: ตัวที่ใกล้เป้ากว่าไปก่อน
- ระหว่างเฉลยผลมีแถบบอกเฟส · ดูกติกาเต็มได้จาก 📖 กติกา · ออกกลางเกม/สอนเล่นได้ด้วย 🚪 ออก
- สิงโตล้ม = ฝูงตกรอบ · ครบจำนวนรอบที่ตั้งไว้ (5 / 8 / 12 / 20 · ค่าเริ่มต้น 8) นับพลังชีวิตที่เหลือ

## Netcode (lockstep)
ทุกเครื่องมีสถานะเกมเหมือนกัน แล้วรัน `resolve()` ตัวเดียวกันด้วยคำสั่งชุดเดียวกัน ผลจึงตรงกันทุกเครื่อง:
1. server เปิดรอบวางแผน (`plan`) + จับเวลา · โฮสต์คำนวณคำสั่งบอทแล้วส่งขึ้นไป
2. ผู้เล่นส่งคำสั่งตัวเอง (`orders`) และกดพร้อม (`ready`)
3. ทุกคนพร้อม/หมดเวลา → server ส่งคำสั่งทั้งหมด (`resolve`) ให้ทุกเครื่องเล่น animation เอง
4. แต่ละเครื่องส่ง hash ของสถานะหลังเฉลย (`done`) · ถ้าไม่ตรงกัน server แจ้ง desync

คนหลุดกลางเกม → บอทเล่นแทนที่นั่งนั้น · โฮสต์หลุด → คนถัดไปเป็นโฮสต์ (คำนวณบอทต่อ).
เป็นแบบ trust-based เหมือน pixel-arena: client รู้ตำแหน่งทุกตัว (หมอกเป็นแค่การแสดงผล) เหมาะกับเล่นกันเองในวง LAN
